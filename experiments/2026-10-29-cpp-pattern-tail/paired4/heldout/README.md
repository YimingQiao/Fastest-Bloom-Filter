# Held-out paired4 decision

The frozen candidate was tested with seeds3253 and9283 across120 workloads/240rows, seven repeats each. All outputs, allocation sizes, and false-positive counts match the original. Source and binary hashes exactly match training; `audit.json` records the checks. `regressions.csv` retains every positive per-seed latency increase, including the unchanged insertion metric, without hiding small control regressions.

**Do not promote this version unconditionally.** The raw batch4/5 gains repeat, as do several longer-tail gains. However, the small-filter4096 control remains slower, small63 loses about3.6–3.7%, large28 loses about2.8–3.7%, and large8 pure lookup loses about5.7–7.3%. A separate dispatch experiment may be warranted, but was not implemented during this confirmation.

Values are the geometric mean of two paired **new/old latency** ratios; brackets show the minimum and maximum per-seed ratio. Below1 means faster. This is a single-machine/compiler,50%-hit benchmark using the existing noinline batch API; it does not establish inlined scalar API behavior.
