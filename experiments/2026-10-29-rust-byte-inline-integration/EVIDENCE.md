Only `rust/src/byte_split.rs` changed: public `contains_hash` now uses `#[inline(always)]` instead of `#[inline]`. The complete file is byte-for-byte equal to the validated one-hint source in commit `d6624a36cd8f08c8ffbbff061324d0d1d7d53b3d`. Parent production commit: `50990cab97c2c561ea4a9e8e438ee8f8b369c48d`. `production.patch` and `provenance.json` record the exact change and old/new hashes.

This accepts the documented tradeoff from the isolated Byte96 comparison: visible public-query throughput improves, while some large actual16bpk staged-hash batch3/31 cases were about2–3% slower. No all-workload or global-fastest claim follows. The older measurements and losses remain unchanged in `../2026-10-29-rust-byte-inline-only-analysis/report/DECISION.md`. No new performance timings were run for this integration.
