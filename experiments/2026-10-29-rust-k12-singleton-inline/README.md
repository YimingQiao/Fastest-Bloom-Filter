# One Rust K12 singleton-chain inlining candidate

This isolated experiment changes exactly two existing `#[inline]` hints to `#[inline(always)]`: public `contains_hash` and private `contains_scalar`. All native function bodies, bitmap/address/mask rules, runtime backends, public bulk routing, insertion, allocation and parallel code are unchanged. Cargo package/library identity distinguishes the clone. The unchanged K12 crate remains a same-process control, and Split64Range remains unchanged. No production source is edited.

The completed Rust108 caller emits one outlined `contains_scalar` call per visible query, with six saved registers and a72-byte caller frame. Forcing only the private hint could move the outline to the public method, so this **single candidate** fixes both ends of that exact chain. There is no hint or variant search. The private helper also serves bulk scalar/remainder paths; therefore bulk regressions remain part of the comparison.

The actual caller derives the committed21-configuration benchmark and adds one public adapter. Every original adapter and the complete timed/workload/validation body stay byte-exact. The new adapter has the same inline forwarding wrapper already applied to the old adapter. Focused normal/ASan checks compare entire old/new bitmaps and all dense outputs, including duplicate/partial insertion, tails, guards and immutable inputs. Prior backend/parallel algorithm proofs are reused; they are not rerun as a broad suite. Actual linked visible/prehashed and fused/raw caller assembly must show whether the candidate still calls a singleton helper. An unsuccessful inline result will be retained without another candidate.

`protocol.json` prespecifies a possible72-row internal comparison: three already-observed Rust108 seeds, both sizes, actual24 bits/key, batches1/3/31/4096, unchanged four query and four build boundaries. Calibration is disabled; no new false-positive sample is collected. The original108 quality records are context only after exact mapping/bitmap/output identity, never pooled across hints or batches. This is a code-generation and regression experiment, not fresh validation against all external libraries. No performance execution is authorized by this source proposal.

No new algorithm or expected speedup is claimed. Candidate-specific code layout and changed scalar fallback code may affect any contract; all losses must be retained. The three-row permutation and four-mode phase ordering are source-derived, with no claim of balanced row positions.
