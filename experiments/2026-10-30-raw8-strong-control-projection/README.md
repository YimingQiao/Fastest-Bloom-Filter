# Complete raw8 strong-control projection

This is a source-only projection protocol. It adds no ranker, executable loader,
filter implementation, workload or runtime authorization. No in-progress raw8
result, geometry value or selected identity was read to prepare it. The current
786-row producer and its pre-frozen calculation remain unchanged.

The calculation at `ca83c8770fc054d28943e6f85fdf618e3576fe47` already exports
the complete selection relation in `views.json`: two sizes, three query-batch
tags, three actual-byte caps, three FPR thresholds and four separate metrics,
giving 216 views (108 query and 108 build). Every view includes all exact tied
leader identities for five ownership classes and four composites. It also
exports every 28,296 allocation alternative and 262 API quality records. There
is no need to recompute minima, Wilson intervals, tie tolerance or eligibility.

After the actual raw8 session 98863 exits successfully, the complete raw archive
must be committed and the frozen loader at
`c30592d5eaf6b0294e869137edfcced043ab7002` must replay the entire producer audit.
Its complete result archive must then be sealed and committed. Those exact raw
and result commits and manifests are prerequisites for any projection; they
are intentionally not populated in this pre-data protocol. The loader's actual
terminal, full 18-case ledger and 786-row audit remain required. A partial table,
unsealed result, branch name or current working-tree output is not an input.

Take the union of every `configuration_ids` entry from the five base ownership
leaders in all 216 views: production native, optional native Range, optional
native K12, retained external and new fastbloom-rs raw8 external. Keep all exact
ties, including a configuration that wins only one build or query contract.
Do not collapse requested allocations, names or size-specific identities.
The four composite leaders cannot add an identity: each composite is a union
of base classes with the same eligibility and latency comparison, so every
composite minimum is also a minimum of its own base class. Their original
entries remain linked as provenance, including nulls.

The existing complete `views.json` is the authoritative per-view ledger.
Preserve all 1,080 base-owner selection slots (five times 216), including empty
leader arrays and null latencies, and all 864 composite slots through exact
file hashes and the committed result archive. Preserve the full alternatives,
quality records, API comparisons, fixed/default comparisons and source catalog
the same way. This projection does not replace or prune those artifacts.

A future finite ledger needs only a mechanical identity join: collect the
union IDs from the already-produced leader arrays, join them to the existing
quality identities, and copy the public API/constructor metadata from their
audited raw rows. The first batch1 source row is canonical for construction
metadata; all three matching rows must agree on that metadata. Keep every
selecting view and owner label as a provenance reference. `protocol.json`
lists the allowed identity fields. Query scratch is contract- and batch-specific
and must not be silently copied from one batch to another.

No latency, trial vector, false-positive count, Wilson interval or historical
qualified flag is imported into a new measurement row. Old values remain
available only in the linked training evidence. Each future row starts with
unmeasured latency and unresolved qualification. A configuration absent from
this finite union is not thereby proved inferior for new seeds, mappings,
clock boundaries or compiler code generation.

All 28 natural-Poppy forms remain unconditional additions under the separate
committed plan `4e9db11302f174a8b9ec0edf8b433e9e8c380a0f`: 14 historical
constructors, each with public byte8 and typed-u64 input. Their public hash
contracts and quality samples stay distinct. None may be dropped because it
has no identity in this raw8 binary. Their first matching future screen rows
receive the prescribed new cal26 samples; old Poppy shared-prehash results
and this raw8 screen cannot qualify either natural form. The 14-constructor
historical shortlist is not an exhaustive natural-Poppy search.

The integrated native K12 SingleLine self-baseline is retained for any later
Rust SIMD comparison even if it is absent from a particular leader union.
The proposed SIMD candidate is a separately proved implementation, not a
renaming of its self-baseline. This projection does not choose its profiles,
seeds, row order, repeats, input domains or final matrix. Those require a
separate finite protocol after the complete training report. It makes no
strongest-library, fresh-seed or performance claim.
