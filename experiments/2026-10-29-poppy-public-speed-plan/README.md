# Poppy shared public-API speed comparison: fixed proposal

This proposal adds the completed public Poppy geometries to the same Rust
query/construction caller as retained native and external controls. No compiler,
filter or performance run is part of this source-selection stage.

## Fixed competing set

The original86 public Poppy choices define49 source mapping groups. Select the
first constructor in the original ledger for each group, independent of its
observed quality or speed. The grouping fixes real capacity, bucket count,
cache size and bucket probe count. Poppy's public insert/query work reads those
fields and the evolving count/bitmap; the policy flag is a serialization tag
after construction. The completed semantic/calibration stages retain all86
choices and equality observations. This does not claim full-load serialized
equality for every source-labelled alias or time every spelling separately.

Two canonical Speed geometries use33 actual bits/key and exceed the maximum
32-bit ceiling. Their complete accuracy results stay in the exclusion ledger.
All47 fitting mappings are timed, including every quality failure. No Poppy
geometry, probe count, requested FPP or speed winner is selected from new data.

For controls, take the union of **every** production-native, external and
optional-Range leader, including ties, from all432 query/build views in the
completed Rust336 analysis. This yields32 exact size/API/actual-byte points.
It retains Bloomsday, public Fastbloom K6/K7, SBBF where it led, all four original
native layouts and the selected Range allocations. Add original K12@24 at both
sizes as a fixed bulk control. Neither rejected inline variant nor future
unmeasured optimization replaces this control during the experiment.

That is81 geometries:47 Poppy,32 prior leaders and2 K12. Poppy's fixed public
constructor arguments run under the smallest fitting16/24/32-bit byte ceiling;
the constructor still uses the real n and its exact original FPP bits/policy.
All ranking uses actual bucket-plus-cache bytes, never the declared ceiling as
an allocation estimate. Smaller allocations remain eligible under larger caps.

## Same compiled public work

Derive the original21-configuration K12 Rust caller at72625673, append47 Poppy
public adapters and leave every old adapter and complete timed/workload body
unchanged. A Poppy adapter passes each supplied common hash as eight little-endian
bytes to public `insert_bytes`/`contains_bytes`. Byte/iterator preparation and all
mandatory cache, bucket and secondary-hash work remain inside the clocks. No
private lookup helper or prepared-iterator cache outside timing is permitted.
Poppy has no native batched membership API here; its bulk adapter loops over the
public byte API. Its visible singleton forwarding has the same inline opportunity
as other adapters. All families use one toolchain/ISA/optimization context.

Retain the existing four query contracts: staged prehashed, staged common-hash,
visible public-single and visible fused common-hash. Retain all four serial
construction boundaries, including allocation and hashing. Insertion uses the
whole input; construction holds one filter at a time and includes public error
handling. Eight query repetitions use the existing balanced four-phase schedule.
Eight construction repetitions retain the original fixed pure/hash ordering;
no build confidence intervals are inferred from stored medians alone.

## Finite launch and quality contract

Use real n65,536/33,554,432, batches1/31/4096, q2^22,50% source hits and the
unchanged seen construction seed42. Group configurations by size and declared
budget. There are18 size/budget/batch processes per round, with only the selected
matching public types in each process. Two complete rounds produce36 processes
and486 rows. Round2 reverses the complete outer process ledger and, after the
original workload/job shuffle, reverses each process's filter list. The extra
flag consumes no RNG. Each group therefore observes both relative filter orders. Calibration is26 in
round1/batch4096 and0 in round2, so the rounds describe reversed schedules;
they do not isolate an order effect from prior calibration/cache/thermal state.
Across-budget leaders remain cross-process comparisons, explicitly identified.

Every API/geometry gets exactly one2^26-negative calibration in round1/batch4096,
after timing. Other batch/round rows set calibration0 and may reuse that one
record only after constructor and input/output fingerprints, mixed counts and
the frozen deterministic mapping agree. Each actual caller checks every output
element against its own canonical reference. Cross-process checks compare full-
output checksums and counts; they do not claim full-array byte comparisons.
The fixed calibration range starts atbase+n+2^22 and is disjoint from
inserted and mixed-query keys. Poppy's calibration and mixed counts must also
reproduce its committed public-worker observations. Retained controls get the
same2^26 denominator; the prior2^24 samples select controls only, not new gates.
No denominator is pooled or increased after a result. The81 API/geometry
records use the same seed/negative stream and are correlated observations,
not independent samples. All81 quality records,
failed choices, two-round timings and allocation alternatives remain.

Rank each round independently under actual16/24/32-bit ceilings and1%/0.1%/0.01%
FPR ceilings, using separate two-sided95% Wilson upper bounds. Keep Poppy,
previous external controls, production native, optional Range and optional K12
owner sets distinct; a combined native winner is not a production-only winner.
Missing eligible comparators are not wins. These are seen-input training results,
not fresh-seed confirmation, multithread evidence or a universal-fastest claim.

The actual caller needs bounded normal/ASan checks of the new generic adapter,
constructor table, full public output/serialization fixtures, strict order flag
and actual public call/timer assembly. Reuse the already passed86-configuration
algorithm proof; do not repeat a broad library matrix. Preserve failures and seal
complete raw data before analysis. Source review and a frozen executable are
required before a separate performance lease; this proposal launches nothing.
