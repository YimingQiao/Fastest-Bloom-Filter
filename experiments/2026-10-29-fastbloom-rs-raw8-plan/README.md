# fastbloom-rs0.5.10: public raw-eight-byte comparison proposal

This is a source-only actual-adapter/geometry/contract proposal. It does not compile, allocate a filter, calibrate or measure performance, and it reads no unfinished Poppy results. The new dependency is `yankun1992/fastbloom@ea18d38eca9cb3a48f395f28ab67004b6f1ab83e`, package `fastbloom-rs`0.5.10, distinct from the already measured `fastbloom`0.17. The [pinned public API audit](../2026-10-29-additional-rust-baseline-api-audit.md) remains the provenance starting point.

## Chosen raw-only contracts

Reuse the immutable Rust caller at`72625673e6b5bb57874a5fa53e04d23ffb8c6ab2`. Its raw paths and workload/helpers are also byte-identical within the pre-data Poppy caller`235090460f5bc063109c1cb3d40357673f36d50e`; no Poppy result participates. `derive.py` extracts the exact aligned-buffer, SplitMix/shuffle, median, full dense-output/checksum/guard, consumption and Config helpers. Future CLI derivation retains the same unique raw-u64 insertion stream, hit generation, shuffled mixed-query stream, selection validation and disjoint absent-counter interval. The existing clock mechanism, output-consumption pattern and data helpers are reused, but raw dispatch and the complete construction boundary are explicitly changed. This is not a claim of old raw whole-body or machine-code identity.

There are exactly two query contracts and two construction metrics:

| Contract | Actual native / retained prehash APIs | fastbloom-rs public API |
|---|---|---|
| `raw_batched_public` | Within each batch, common`hash64` preparation then the unchanged public bulk method. | Direct public`contains(&raw.to_le_bytes())` loop over that batch; no artificial identity-copy pass. |
| `raw_visible_public` | One non-inlined whole-array loop with common hash plus actual public singleton, visible to the optimizer. | The same loop boundary, with eight-byte preparation and actual public`contains` visible to the optimizer. |
| `raw_insert` | Common hash preparation plus public insertion, once the filter and required scratch are ready. | Direct public`add(&raw.to_le_bytes())`, once its filter is ready. |
| `allocate_filter_and_scratch_raw_insert` | Required hash-scratch allocation/initialization, filter constructor and raw insertion. | Filter constructor and raw insertion; required scratch is zero and no buffer is allocated. |

`RawFilter::scratch_words(len)` declares required workspace: CommonHash returns len, and DirectRaw8 returns0. Zero uses `None`, not an `Aligned::new(0)` one-byte allocation. Each timed build starts its complete clock before required scratch and filter allocation/initialization; the insertion-only clock starts after both are ready. That build's scratch is released after its untimed validation. The canonical filter's build scratch is likewise dropped before queries. Query storage is only the API-required batch workspace, and `build_scratch_bytes`/`query_scratch_bytes` are reported separately from actual filter bytes. The old uniform maximum scratch allocation is removed, so whole-input CommonHash cannot hide256MiB outside the complete clock and DirectRaw8 pays for no unused buffer.

Insertion batch size remains independent of query batch. The source supports full-input or bounded insertion chunks such as4096; a later fixed protocol must choose its insertion workload before data. No whole-input optimum is assumed, and no extra algorithm variant is introduced. Filter-byte quality caps do not silently include or erase caller scratch: construction reports expose the necessary extra space explicitly.

Every library's required hashing is inside these clocks. The upstream two seeded XXH3 computations remain in the unmodified public implementation; they are not precomputed by the adapter. Normal compiler elimination/lazy evaluation remains allowed and will be reported by the actual caller's ASM. This is an end-to-end raw-key comparison, so different public hash functions are part of each implementation. There is no `prehashed`, `pure`, artificial identity-copy leader, or index-vector query column. A smaller measured raw cost may result from hashing, addressing, probe count or the whole public implementation; it is not an isolated bitmap-kernel conclusion.

`proposed/raw_contract.rs` contains the static CommonHash bridge and direct raw API contract. `proposed/fastbloom_rs_adapter.rs` implements the actual upstream public constructor/add/contains calls. `proposed/reporter.rs` is the proposed raw-only clock/validation core. All adapters get the same `inline(always)` singleton-wrapper opportunity; upstream/native public hints and bodies remain unchanged. The public bulk-loop fallback does not pretend that fastbloom-rs has a native SIMD bulk API.

## Fixed m/K and rival catalog

The new panel is fixed before data: real n=`2^16` and`2^25`, actual16/24/32 bits per key, every public K from1 through24, giving144 configurations. This includes upstream real-n optimal counts12/17/23 without duplicate special entries. Keeping all24 avoids assuming monotonic latency or choosing only convenient quality neighbors. No salt, seed, hash policy or internal library code is tuned. Whole64-bit words are required; the public explicit constructor itself does not repair a non-word-multiple m. Every new point fits the exact byte ceiling and the supported multiplication range safely fits u64; the independent oracle uses u128 arithmetic.

The control catalog retains all112 constructor geometries from the complete committed public-K calibration, plus six current native K12 geometries. This yields118 controls and262 total geometries. It includes all production families, optional native Range/K12, Fastbloom0.17 K1..12 plus its public real-n default counts11/17/22, Bloomsday and SBBF. Native16-bits-per-key aliases at requested24 are not repeated as distinct allocations; actual16 remains eligible under cap24/32. The native library source will be snapshotted at`ba5530a4fc38930a9da4593f2a8af7d1de3c853a`, including the proved optional SingleLine K12 public API. The old experimental K12 is not relabelled as native.

`selection.json` is generated from only constructor columns of112 committed records at`b94dc7b...`, plus source-defined new/native K12 geometry. Old quality and timing columns do not select, prune or rank anything. No Poppy measurement is read; Poppy is outside this initial catalog. Any addition based on its eventual complete evidence must be prespecified before execution. This catalog cannot support a claim against all external libraries.

This proposal fixes the constructor catalog, not a formal measurement command ledger. All262 points at batches1/31/4096 would be786 rows; that potential cost is explicit. A later root-reviewed finite protocol must choose exact commands, rounds, seeds/input envelopes and CPU lease before data. No new point may be removed because it fails quality, and no K-neighborhood-only timing shortcut is assumed. Caps16/24/32 always admit every smaller measured allocation. Per-construction Wilson95 upper gates at1%/.1%/.01% are unpooled; aliased API repetitions are not independent observations.

## Allocation and semantic proof required before execution

The public constructor is `FilterBuilder::from_size_and_hashes(m_bits,K).build_bloom_filter()`. Its inferred `expected_elements` is metadata only: the workload always inserts the original real n and never substitutes the inferred value. Public `config()` and `Hashes::hashes()` verify m/K. Borrowed `get_u8_array()` provides the bitmap length without serialization copying. At the pin, the bitmap is one`Vec<usize>` created by`vec![0; slots]`; inline builder/filter fields are not a second heap allocation. Actual backing must still be established with an allocation ledger before this borrowed length may populate `actual_bytes`.

A bounded future correctness stage should verify all24 K values on small ordinary/non-power-of-two word counts using an independent complete-bitmap oracle: public XXH3 seed0/32 on the same eight bytes, u128 progression modulo m, explicit per-bit setting. It should check every inserted key, duplicate/collision history, raw extrema and endian encoding, full dense query outputs, tails/offset guards, immutability and invalid output length before any write. The public `get_hash_indices` helper is not a timed shortcut and need not be used by the adapter. Validate constructor allocation/deallocation and zero extra bitmap copies, including the six formal sizes and K endpoints; confirm K cannot change the allocation formula from the pinned source and small all-K observations.

The actual caller then needs focused normal/ASan checks, old raw-control semantic reproduction on seen tiny inputs, exact CLI rejection, two-phase schedule and deliberate output-corruption guards. The proposed paired schedule is AB/BA/BA/AB with a seed-derived label permutation, repeated for eight samples per query contract. Before each timed query, its complete output region is poisoned with a non-0/1 value outside the clock, identically for every implementation. Warmup, each build-validation chunk and each calibration chunk poison their written regions too. This prevents a skipped write or tail from inheriting a prior correct answer. Every timed query's full vector, checksum and guards are checked outside its clock; every inserted raw key is checked after each timed build. The actual caller fault gates include both skip-last-write and wrong-value corruption. Query and construction trial vectors are recorded directly; nothing is inferred from absent vectors. One filter lifetime is timed at once; the reference bitmap used in focused tests is destroyed before timed builds.

The calibration raw interval is exactly `[key_base+n+q, key_base+n+q+2^c)`, disjoint from insertion and timed-negative counters. It uses the same raw API as insertion/warmup/hits, then checks each dense answer against the public raw singleton. Common-hash and direct-raw data must never be mixed for one filter. Actual native/raw-visible and fastbloom-rs public call paths must be inspected in the new executable; old latency or old assembly is not imported.

The initial source draft preallocated `max(query_batch,insert_batch)` scratch outside construction clocks for every API. Root identified that unfair boundary before source commit/build/data. [scratch-accounting.patch](scratch-accounting.patch) records the exact pre-data correction; constructor catalog and upstream algorithms do not change.

The later output-validation correction is separately preserved in [output-poison.patch](output-poison.patch). The [bounded allocation/caller proof plan](ALLOCATION_PROOF.md) requires runtime evidence for scratch sizes, lifetimes and clock events before execution.

No dependency resolver or compiler has run for this proposal. The upstream package also declares fastmurmur3, cuckoofilter and xorfilter-rs dependencies even though this adapter uses only BloomFilter; they must not be stripped or silently replaced. Exact upstream source/license, Cargo lock and all transitive package trees must be frozen before the focused actual-caller build. Shared dependency changes are reported and all controls use the same new binary/graph. Compiler inputs are collected by structured package/manifest/target identity, with exact literal/normalized Cargo dep-info aliases and ambiguity rejection; failed attempts remain immutable.
