# Required caller and allocation proof (not executed)

This is a bounded correctness plan for the future actual caller. It authorizes no compile, filter execution, calibration or performance run. The 262-constructor catalog is unchanged; insertion batch and query batch remain independent protocol arguments.

The new dependency must first be obtained at the exact upstream revision and retained with its license and complete package tree. Resolve one combined Cargo.lock for the current native snapshot, fastbloom-rs, fastbloom0.17, Bloomsday and SBBF. Freeze every local and registry source, structured Cargo package/manifest/target identity and compiler flags before the first build. Public control bodies retain their original semantics; any dependency-version unification is disclosed. There is no substitute local implementation of XXH3 or the upstream filter.

Use the actual raw adapter and reporter in normal and ASan builds. A small allocation-ledger executable and a test-only raw-filter spy should establish the following independently of reported counters:

1. `FastbloomRsRaw<K>` owns one backing allocation with the public bitmap length, and constructor/destructor deltas return to zero. Check ordinary and non-power-of-two word counts for all K1..24, plus the six formal sizes at the K endpoints. Keep real n, public m and public K in the ledger. Runtime allocator bookkeeping is outside the filter and separately reported.
2. `Scratch::new(0)` produces no allocation, no initialization and no deallocation. The actual direct adapter asks for zero at every tested length. CommonHash asks for exactly `len * sizeof(u64)` live requested bytes, including lengths 1, 31 and 4096. Allocator usable-size overhead, if measured, is a separately named observation rather than silently substituted for requested bytes.
3. A test-only event observer around the actual reporter boundaries records complete-start, scratch-ready, filter-ready, insertion-start/end, validation and destruction. Scratch allocation/initialization and filter construction must lie after complete-start and before insertion-start. Both required resources must be live throughout insertion. Normal measurement builds omit observer state and calls; actual release ASM must confirm the final public calls remain inside the stated clock intervals.
4. At validation of each timed build, exactly that filter and its insertion scratch are live. After validation both are dropped before the next build. Canonical build scratch is released before query scratch is allocated. No timed fresh build overlaps a second reference bitmap. Test `insert_batch < query_batch`, equal batches, `insert_batch > query_batch`, insertion tails and `insert_batch > n`; do not require whole-input buffering.
5. Query uses only the selected adapter's `scratch_words(query_batch)`, reported as caller workspace separately from filter bytes. Common dense-output and raw-input storage are benchmark resources, reported separately when total harness memory is described. The raw-visible contract itself uses no scratch; the paired query lifetime retains only the workspace needed by its raw-batched phase. There is no direct-API identity-copy buffer.

The functional gate uses an independent u128 bit-position oracle over the upstream public two-seed XXH3 outputs, full bitmap equality, every inserted raw key, complete guarded outputs, collisions/duplicates/endian extrema and immutable lookups. All old CommonHash controls use the same original raw stream for insertion, warmup, hits and disjoint negatives. Small seen-seed fixtures reproduce the retained controls' semantics without importing old timing. The actual caller additionally needs its two-phase balance, full-output corruption and malformed-CLI guards. Poisoning occurs before every query/warmup/build-validation/calibration write region and outside clocks. Fault controls must independently omit the last write and write a wrong value; both must fail after earlier successful calls, so stale correct output cannot mask the omission. These focused proofs replace neither the future fixed measurement protocol nor its per-construction quality gates.

After correctness, freeze the actual native/ASan executables and consumed dependency closures. Inspect the raw-visible, raw-batched and insertion public paths for both a current native control and the new direct API. All upstream-required hashing stays inside the raw clocks; ordinary compiler elimination is allowed. No existing prehash column is repurposed, no old throughput result is copied, and no performance ranking is produced during this proof.
