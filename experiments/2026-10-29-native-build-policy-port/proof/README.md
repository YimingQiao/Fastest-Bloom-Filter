# Actual native before/after caller proof — source preparation

This stage has not been compiled or executed. It derives both immutable native
snapshots from before `e8b89cd3` and after `2b3469f0`. `derive.py` reads committed
blobs, records every origin, and verifies exact generated bytes. The only C++
namespace substitution is `bloom_filters` to `native_before`/`native_after` across
each complete local header dependency closure. Both original closures are also
retained: the focused C++ boundary executable uses the unchanged after snapshot,
not its namespace derivative. Rust copies preserve library source, licenses and
NOTICE; only package identities in Cargo metadata differ so both libraries can
coexist in one binary. No copied-library API hint is changed.

The before/after benchmark uses actual public native types. C++ `NativeBinding`
only selects a type and invokes its constructor. Rust `Native` is monomorphized
static forwarding with no policy logic; its `BOUNDED` constant is used solely by
outside-timer metadata validation. The original requested T reaches the real
native public insertion method between clocks. No experimental `Filter<Enabled>`
policy wrapper remains. Both caller patches from the previously validated harness
are saved under `changes/`; workload construction, phase order, timer placement,
input checks, single-bitmap lifetime and guarded complete outputs are retained.
The old wrapper's timings are not imported or normalized into this track.

The proposed preflight builds normal and ASan C++/Rust and executes 24 paired
caller records (six per language/backend). These cover empty insertion plus
allocation, the 65,537-key boundary, and populated incremental insertion. It also
executes the actual focused library tests: 12 incremental cases per language and
backend, plus 192 pure request boundary combinations each, totaling 48 real cases
and 768 pure helper cases. The focused test children have three allowed physical
cores to make automatic scheduling meaningful; compiler jobs remain on the
primary core. Implicit C/C++ flags, Cargo encoded flags/wrappers and loader/allocator
overrides are rejected and recorded before building. Native automatic worker counts may differ by language and are
compared against each language's unchanged scheduler under the same affinity.

Full old/new membership, all 32,771 mixed answers, output guards, exact worker and
scratch accounting, four injected-output failures and ten malformed CLI cases
remain mandatory. Every consumed compiler input is captured, including all Rust
`.d` files, both native crates, the public caller and native boundary tests. Fresh
output/build directories reject both existing paths and dangling symlinks. A
failure leaves its source and logs intact for a versioned follow-up.

After successful correctness, capture both actual native callers/public methods
and inspect selection relative to clocks before freezing binaries for any
performance run. No claim about instruction placement follows from source alone.
The later native performance stage must preserve the complete fixed96 ledger,
including all known outside-gate regressions. Reused seeds are explicitly seen
inputs. There is no new threshold search, default-merge decision, external
ranking, query-speed claim or throughput result in this preparation.
