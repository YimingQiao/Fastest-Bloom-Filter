# Natural-Poppy full-load quality component

This source-only plan collects one new full-load calibration for each of the 14 historically shortlisted constructors through each of its two proved natural public APIs: 28 separate records. The exact constructor/form identities are in points.json. Public byte8 and typed-u64 remain distinct mappings with no common prehash, no artificial scratch and no shared denominator. Every constructor uses its real n, exact FPP bits/cache policy, full insertion population and bucket-plus-cache bytes. The completed bounded proof7e5daacc established caller semantics and allocation/codegen, not these full-load FPRs.

Use the unchanged proved native binary42174b03 and dependency graph. The initial natural bridge uses seen training seed42, q=2^22, requested hit50%, and independently fixed insertion chunk4096. This fixes a workload before natural-form observations; it is not a fresh-seed claim. The insertion, mixed-negative envelope and new calibration interval are recorded in input-domains.json from the exact caller SplitMix draw. Each calibration interval starts at key_base+n+q, disjoint from inserted keys and mixed queries in that construction. Intervals across different sizes need not be independent; no counts are pooled.

Every form receives a uniform2^26 negatives, for1,879,048,192 new answers across28 records. These are new observations of the natural public mappings. Historical shared-prehash Poppy counts and latency supplied only the finite constructor shortlist and are never used as new qualification. Gate each record separately with the pointwise two-sided95% Wilson upper endpoint at1%,0.1% and0.01%, charging actual bucket+cache bytes. Preserve every failed or borderline gate. Do not extend only failures, substitute constructors, omit an API, or treat a finite upper-bound miss as permanent algorithmic disqualification. The14-constructor shortlist is not an exhaustive natural-API search; unselected historical points may behave differently under typed/raw input.

**Combine calibration with the first matching row of the later frozen natural raw screen. Do not launch a separate quality run.** The existing caller's canonical filter already serves both query measurement and the disjoint calibration. The first matching batch1 row collects cal26; later rows use cal0 and reference that record only after exact constructor, actual bytes, raw workload, full mixed-output fingerprint/counts and other protocol identity fields match. Different seeds, input intervals, constructors, forms or unproved binaries require their own calibration. Reuse does not increase a denominator.

This avoids an extra stand-alone population pass and its repeated builds. The unchanged reporter performs `repeats` complete timed build lifetimes plus one canonical construction. Even its minimum four repetitions would construct each full filter five times for a supposed quality-only invocation, then discard valid timing work. Attaching calibration to a useful later screen incurs no additional construction: the same canonical bitmap supplies both its query observations and its new quality record. It does not eliminate the reporter's own repeated build trials or the canonical construction in other measured processes. A future query-only reporter could reduce those builds further, but would be a separately reviewed source/binary change; none is introduced here.

The final runtime ledger, repetition/round choices, strong raw-compatible rivals, placement and performance analysis remain unresolved. They must use the complete committed786 raw8 evidence; no partial raw8 values are inputs. This proposal contains no executable launcher and authorizes no filter, calibration or timing run. It also creates no current natural-Poppy speed/leadership claim. Once the full screen is fixed, its loader must preserve all28 new quality identities and every loss, plus any additional separately required seed records.
