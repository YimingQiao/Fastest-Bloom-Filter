# Rust short-entry V4 design note, 2026-10-29

Status: unimplemented hypothesis. V2 and V3 remain rejected production changes. Their original source snapshots, guards and results stay unchanged in [the isolated API experiment](2026-10-29-rust-single-api/README-v3.md).

V3's public checked inline entry proves equal input/output lengths, then calls a private non-inlined bulk method. The private method receives two independent slices, so LLVM cannot reuse the outer equality proof. Its generated loops still compute `min(input_len, output_len)` and introduce one-element loop peeling. This is observed code generation; it does not establish that those instructions explain the measured regressions.

One future isolated candidate can pass `hashes: &[u64]` plus `out: *mut u32` to a private unsafe bulk helper. The safe public entry first asserts equal lengths and retains the direct singleton branch. Only for the bulk call, it passes `out.as_mut_ptr()`. The helper immediately reconstructs `from_raw_parts_mut(out, hashes.len())` and runs the unchanged original bulk kernel. Both slice lengths are then derived from one value inside the optimized body. It may still require a non-singleton assumption or guard; matching lengths alone does not prove `len != 1` to the private optimizer. Inspect code before claiming either check disappeared.

The private safety precondition must state that `out` is non-null, aligned, writable for `hashes.len()` initialized `u32` values, exclusively borrowed for the call, and non-overlapping with the input and filter storage. The only callers must be audited safe public entries holding the original `&mut [u32]`; do not expose the pointer helper publicly or manufacture a longer slice. Zero length must remain valid using the non-null aligned dangling pointer supplied by an empty mutable slice. Do not use an unchecked length assertion as a substitute for this caller contract.

An orthogonal later Byte-only entry policy could process lengths one through three through the existing `contains_hash` loop before entering private bulk. It addresses V3's persistent batch-three loss but changes control flow beyond the equal-length proof. Keep it a separately named candidate and preserve all controls.

Required gates before any promotion: normal, disable-avx512 and ASan full-output/guard/no-FN tests, mismatched-length panic before writes, zero and singleton cases, offsets/tails through 131 plus 4096, independent bitmap checks, and actual native-port parity. Same-process performance must retain immutable original, V2/V3 as appropriate and new candidates, cover batches 1/3/4/8/31/4096 at small/large actual16/32bpk, and retain symmetric upstream singleton controls for final ranking. A new CPU must be recorded and compared only within its own same-process trials. No source change or compute is authorized by this design note itself.
