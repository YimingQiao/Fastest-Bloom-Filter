# Native optional C++ K12 correctness

All four requested profiles passed on the first attempt: GCC 12 native AVX-512, AVX2 without AVX-512, portable without AVX2, and native AddressSanitizer plus UndefinedBehaviorSanitizer. The two new CMake targets were exercised. The unsafe old generic parallel wrapper failed compilation on the expected private `CacheLineCount` access; only the dedicated K12 wrapper can access private geometry.

The native source is `6e7df603a02e2e7d1c226afaff6d37c14f841f3b`, based on accepted optional Range commit `81f40f16caa44586537d577f998c33fec4c22be8`. Lab preparation is `fd798e7939e80ffb021d271b6e202da1f4b5ffc4`. Serial insertion, query, mask and range-reduction expressions remain unchanged from the measured K12 prototype; reversible source derivation verifies the original complete header after undoing names, include routing and access declarations.

The dedicated parallel API assigns each key using its actual top24-derived physical line, `floor(line * workers / lines)`. Tests include an explicit case where a high32 hash partition would disagree, ceil partition boundaries for non-divisible worker/line counts, a maximum-capacity arithmetic boundary, full serial/parallel bitmaps against an independent per-bit oracle, every required probe bit removed, duplicates, distinct successive insertion batches, complete dense outputs, guarded tails through 131 and around 4096, zero/null operations, and checked constructor/scratch overflow. Representative capacities include non-power-of-two line counts and a bitmap above the prefetch threshold. T3 and T7 are real effective worker counts for the large input fixtures.

The whole run held the socket0 lock. Compilation used CPU2; test processes were explicitly allowed on CPUs 2,4,6,8,10,12,14. Sysfs confirms seven distinct socket0 physical cores. Threads were free to migrate within that mask; this is not a claim of per-thread pinning. There were 18 recorded commands: 17 successful commands and one intentional compiler rejection. Four executable hashes and 348 actual compiler inputs are recorded, with all consumed worktree inputs checked against the native commit. Generated CMake records also describe unbuilt targets; only the explicit build commands and four test executions are claimed.

No benchmark, new false-positive calibration or speed comparison ran. The API remains optional, default selectors are unchanged, and no bounded-worker optimization was introduced. Prior evidence still includes substantial singleton/batch1 losses and workload-dependent narrow quality margins; passing these checks does not remove those limitations. Concurrent independent writes or overlapping mutation/queries still require external synchronization.
