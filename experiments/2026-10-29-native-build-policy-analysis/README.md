# Bounded-policy analysis source

Prepared before reading or ranking any completed performance values. The fixed
matrix had already completed when this additive analyzer was written; this is
not a claim that the analysis source itself was committed before measurement.
The measured policy, two input seeds, six scenarios and four-trial order were
frozen beforehand and are unchanged.

The loader accepts only raw commit5677deae and requires its exact196-file
inventory plus the frozen producer's full command/source/phase/semantic audit.
The output keeps160 candidate/control contracts,320 arm/serial comparisons,
480 primary metric vectors,288 separate prefill diagnostics and80 seed-range
records. The latter combine only the two seeds at an identical language,
family, scenario, T and contract; no scenario, allocation or language is pooled.
There are48 active-gate contracts and112 unchanged-policy controls. Every loss
survives; all four trial values and matched-repeat ratios are retained.

Primary speedup is control/candidate, so greater than1 favors the candidate.
Serial overhead is arm/serial, so greater than1 is slower than direct serial.
The shared serial sample is referenced twice when comparing two variants, never
represented as two independently measured controls. Exact ties remain ties.
Populated allocation+build has no record; empty setup zeros are marked as no
measured prefill. Ratios are descriptive, without significance intervals or an
automatic production decision.

After source-only peer review/freeze, the analysis runs onCPU4 using existing
Python only. It does not invoke a filter or compiler. Practical interpretation
must assess each active-gate benefit against each outside-gate regression and
the serial baseline. It cannot extend the threshold, claim query improvements,
choose a seed, or treat this internal policy comparison as an external ranking.
