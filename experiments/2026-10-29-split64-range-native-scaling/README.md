# Native Split64 / Range API scaling preparation

This source-only follow-up implements the construction/native-API part of plan `333759a`. It has not been compiled or measured. C++ and Rust library sources are exact immutable snapshots: current production Split64 from the preceding reviewed snapshots, and the unchanged validated Range candidate/partition helper from `f3a9f4c`. The copy manifest records every source commit and SHA. Native kernels, dispatch, prefetch, inline annotations and partitioning are unchanged. Both language copies retain their MIT/Apache licenses and attribution notices.

The minimal grid is n2^16/2^25, Split64 at actual16/32 bpk, Range at actual16/24/32, T1/4/8, q2^22, patterned50% hits, seed42 and cal2^24. There are30 configurations per language,60 total. Split's cap24 alias is omitted. FastPattern/FourSector/Byte/atomic controls are deferred; no external implementation is ranked in this stage. Each language is compared against its own same-row serial control, never against a different compiler/runtime's timing.

Every row retains four separate build metrics: serial insert-only, native-parallel insert-only, serial allocate+build, native-parallel allocate+build. These use separate fresh bitmaps, not a sum of independently measured durations. Insert-only allocation happens onCPU3 before expanding affinity outside the timer. Allocate+build starts after expanding affinity, so constructor/first-touch may run on any allowed same-node core. All native count, prefix, scatter, insert passes, explicit temporary allocations/destruction and thread creation/joins lie inside the public parallel call and thus its measured interval. Bitmap destruction and validation are outside. No hidden live oracle bitmap competes with a timed build.

Four repetitions form a complete Williams schedule over the four build phases, rotated by seed. Whole-array serial/parallel query calls alternate AB/BA twice, after all build trials and one canonical query construction. Every trial records full vectors and min/median/max. This balanced within-configuration schedule does not balance family/case order or constitute held-out confirmation; one source-derived family shuffle and ordered case groups remain explicit limitations.

The allowed physical-core budget is the firstT of CPUs3,5,7,9,11,13,15,17, on socket1/NUMA1. The runner must expand child affinity before numactl topology validation. Main caller is pinned toCPU3 for raw-array initialization, direct serial controls and validation. Before native parallel calls it restores the allowedT-core mask, inherited by the library's threads; afterward it returns toCPU3. Every expansion/restoration is outside the clock. Native workers may migrate or colocate within that set; there is no per-worker pinning claim. C++ executes worker0 on the caller and spawnsW−1; Rust spawnsW workers and the caller coordinates whenW>1. That extra Rust coordinator shares the sameT-core budget and is reported separately. W1 uses each library's serial fallback.

Native query metrics cover fresh-thread end-to-end public calls on the **whole query array**, including native splitting and joins. They are not the previous external4096-batch shared executor and are not called gated/kernel-only time. Common hash preparation is outside every timing in this stage. API output/bitmap equivalence can be compared across languages; latency cannot be transferred between runtimes.

Each native constructor is checked against exact requested backing bytes. Effective build/query workers and public scratch estimates are reported per row; Rust's extra segment/cursor metadata remains visible. Estimates exclude allocator metadata, runtime thread handle allocations, OS stacks and RSS. The source exposes no private mutable bitmap to the harness. Existing full-bitmap/nondivisible/skew/ownership proofs are reused by immutable source identity. The new harness checks every inserted key and all mixed-query outputs after every fresh timed build; the oracle bitmap is dropped first. Every timed query validates the entire output plus guards. Calibration streams disjoint negatives after all timing, and repeatedT/language observations never add independent probes.

`verify_source.py` performs only text/hash/committed-blob checks. A later additive preflight should compile the new harness normally and under ASan, exercise tiny T1/3 cases and malformed arguments, compare full C++/Rust semantic rows at16/24/32, and verify worker/scratch/phase/affinity metadata. It should reuse existing native backend/ownership suites rather than rerun unchanged library tests. Compilation and performance require separately reviewed freezes and explicit socket leases. No production promotion is proposed by this preparation.
