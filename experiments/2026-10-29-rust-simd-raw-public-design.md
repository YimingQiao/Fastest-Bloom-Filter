## Pinned Poppy public-input audit

Inspected Poppy commit `992a13e27e8b09b2a832333a4ba3d160545fa866`; local README, public Bloom wrapper, v2, PoppyHash and WyHasher files were compared byte-for-byte with that commit. The audited documentation declares no prehashed/uniform-input requirement for byte APIs. The public wrapper describes inserting data and testing bytes; v2 accepts any `AsRef<[u8]>` and delegates to its generic public API. Upstream tests call `insert_bytes("hello")` and exercise sequential integer byte encodings, including u64. This establishes supported input shape, not distribution-independent FPR guarantees. See [public byte documentation](https://github.com/hashlookup/poppy/blob/992a13e27e8b09b2a832333a4ba3d160545fa866/poppy/src/bloom.rs#L275), [v2 public dispatch](https://github.com/hashlookup/poppy/blob/992a13e27e8b09b2a832333a4ba3d160545fa866/poppy/src/bloom/v2.rs#L419), and [counter-encoding tests](https://github.com/hashlookup/poppy/blob/992a13e27e8b09b2a832333a4ba3d160545fa866/poppy/src/bloom/v2.rs#L941). No upstream test was executed for this audit.

For `insert_bytes(raw.to_le_bytes())` / `contains_bytes(...)`, the delegated type is `&[u8]`. Its specialized `PoppyHash` copies inputs of length at most8 into a zero-padded eight-byte array and decodes little-endian. Thus at exactly8 bytes the initial `h1` is the original raw integer, not a WyHash digest. Longer byte strings use the hasher. For typed `insert(&raw)` / `contains(&raw)`, u64 instead uses the default `PoppyHash`: construct `WyHasher`, invoke the integer's standard `Hash`, then finish. `WyHasher` wraps pinned wyhash0.5.0 with seed `0x706f707079533d42`; it overrides `write`/`finish`, not `write_u64`. The inspected Rust core source dispatches u64 Hash to `write_u64`, whose default writes native-endian bytes (little-endian on this host). Pin the actual toolchain and prove that typed public path in the future bridge; do not assume cross-toolchain hash serialization stability. See [PoppyHash implementations](https://github.com/hashlookup/poppy/blob/992a13e27e8b09b2a832333a4ba3d160545fa866/poppy/src/hash.rs#L34) and [WyHasher wrapper](https://github.com/hashlookup/poppy/blob/992a13e27e8b09b2a832333a4ba3d160545fa866/poppy/src/hash/wyhash.rs#L7).

Both paths then share this exact v2 mechanism:

- Start the iterator with initial `h1`, `h2=0`, `i=0`. Bucket hash `h` applies, in order, `x ^= x << 12`, `x ^= x >> 25`, `x ^= x << 27`, then wrapping multiplication by2685821657736338717. The bucket is `h & (bucket_count-1)` for a power-of-two count, otherwise `h % bucket_count`. An enabled cache uses `h & (cache_bit_len-1)`; lookup may reject there before probing.
- Each bucket is4096 bytes, so the first bit position is `h1 & 32767`. Only when requesting the second iterator item does it initialize `h2=WyHasher::hash_one(initial_h1.to_be_bytes())`. On each non-first item, `h1` then wraps by `+h2`, and `h2` wraps by `+i`; the iterator increments `i` and emits `h1 & 32767`. The count is the constructor's `n_hash_buck`.
- Lookup returns at the first missing bit. Therefore the secondary hash can be skipped by a cache/first-bit rejection or a one-probe geometry. Typed-u64 performs its initial hasher before these checks; byte8 avoids that first digest. Preserve these natural early exits rather than forcing equal hash counts. Public insertion checks and Result handling remain mandatory.

These are source facts from [iterator/address logic](https://github.com/hashlookup/poppy/blob/992a13e27e8b09b2a832333a4ba3d160545fa866/poppy/src/bloom/v2.rs#L30) and [public insertion/lookup bodies](https://github.com/hashlookup/poppy/blob/992a13e27e8b09b2a832333a4ba3d160545fa866/poppy/src/bloom/v2.rs#L358). The frozen raw caller generates a shuffled contiguous insertion interval and mixed counter-domain queries; shuffling changes order, not the byte8 `h1` values or first-bit mapping. Bucket scrambling does not replace the iterator's original first `h1`. No FPR, clustering severity or speed conclusion follows here: the two public mappings require their own complete, uniformly budgeted calibration and timing. Adding a client common hash to natural byte8 would change this contract; the old prehashed-Poppy results cannot stand in for it.
